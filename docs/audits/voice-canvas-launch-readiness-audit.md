# Voice Canvas launch readiness audit

Date: 2026-07-20
Branch: `codex/canvas-launch-readiness-qa-v1`  
Scope: ride, appointment, medication refill, shopping or delivery, provider reply, and task hub resume.

## Current status

Status: **automated readiness strengthened; manual real-device/deployed rollback QA still required before launch sign-off.**

This pass found and fixed one launch-blocking rollout issue: provider-reply Canvas had client-side rollout wiring but no matching server feature endpoint. The endpoint now exists and all Canvas feature flags share the same server-side fail-closed resolver.

Manual execution must use `docs/audits/voice-canvas-real-device-run-sheet.md`, prepare sanitized artifact references in `docs/audits/voice-canvas-real-device-evidence-packet.md`, and be recorded in `docs/audits/voice-canvas-real-device-qa-matrix.md`.

Run sheet structure can now be validated with `npm run --silent canvas:qa:runsheet -- --allow-pending --json --output=artifacts/voice-canvas/YYYY-MM-DD-run-sheet-summary.json`. The validator checks privacy guardrails, environment preflight, flow/device rows, behavior recovery, rollback, copy/accessibility, analytics, and closeout coverage; accepts the committed template only with explicit pending-review mode; preserves existing artifacts unless `--force` is explicit; and is included in the combined launch preflight.

Feature endpoint evidence can now be collected from the deployed environment with distinct enabled and rollback-disabled artifacts, such as `npm run --silent canvas:qa:features -- --base-url=https://staging.vyva.app --expected-state=enabled --json --output=artifacts/voice-canvas/YYYY-MM-DD-feature-endpoints-enabled.json` before rollback and `npm run --silent canvas:qa:features -- --base-url=https://staging.vyva.app --expected-state=rollback-disabled --json --output=artifacts/voice-canvas/YYYY-MM-DD-feature-endpoints-rollback-disabled.json` after rollback. The collector performs GET requests only, rejects local/private/placeholder hosts by default, preserves existing artifacts unless `--force` is explicit, and stores only sanitized endpoint/status/cache-control/timing plus expected state, `enabled`, `rolloutPercent`, recognized payload keys, and unexpected-key count. It rejects enabled launch captures unless every endpoint shows enabled true/rollout 100 and rejects rollback-disabled captures unless every endpoint shows enabled false/rollout 0. It does not store raw endpoint bodies or unexpected field names, so schema leaks fail the gate without copying personal data into QA artifacts.

Ride, appointment, and medication refill per-flow rollout runbooks now align with the unified launch rollback gate: rollback requires the enable flag set false, rollout percent set to 0, uncached endpoint proof showing `{ "enabled": false, "rolloutPercent": 0 }`, sanitized `canvas:qa:features` rollback-disabled evidence, named existing fallback verification, open-session Canvas closure/hiding, and explicit no-write/no-resubmission/no-external-action evidence in the real-device run sheet, evidence packet, and QA matrix. `canvasPlatformCompliance.test.ts` now guards those per-flow runbooks against drifting back to payload-only or prose-only rollback instructions.

Feature endpoint manual trace evidence now has a manifest-filled `npm run --silent canvas:qa:features -- --trace-template` output plus copy-safe template instructions in the launch runbook, real-device run sheet, and evidence packet for malformed-config and missing-config fail-closed proof that cannot be collected by `canvas:qa:features`. The template requires exact endpoint and server key, sanitized deployment log/trace/artifact references, disabled false/rollout 0, named fallback visibility, and explicit privacy checks that exclude raw response bodies, unexpected field names, transcripts, entered text, addresses, medication details, provider details, shopping details, account identifiers, and personal data.

Analytics evidence can now be validated with `npm run --silent canvas:qa:analytics -- --input=artifacts/voice-canvas/YYYY-MM-DD-analytics-evidence.json --json --output=artifacts/voice-canvas/YYYY-MM-DD-analytics-validation.json`. The validator requires an object with a non-future ISO `generatedAt` timestamp generated within the last 7 days, a source that identifies staging, production, or a concrete analytics dashboard/query/export/log artifact, `coveredFlows` for ride, appointment, refill, shopping, provider_reply, and task_hub_resume, and positive observed sample counts for started, resumed, abandoned, blocked, confirmed, and completed; accepts only the closed envelope fields `name`, `step`, `input`, `attempt`, `restored`, and optional `revision`; rejects anonymous event arrays, stale exports, and local/mock smoke fixtures; preserves existing artifacts unless `--force` is explicit; and writes only aggregate validation results without copying raw sample rows or unexpected field names.

Analytics validation now also exposes `npm run --silent canvas:qa:analytics -- --template`, which prints a privacy-safe but intentionally not-ready JSON skeleton. The template includes launch-scoped `coveredFlows`, zero aggregate counts, and an empty sample array, so QA can start from the allowed envelope without pasting raw analytics rows; unchanged templates fail validation until filled with real staging or production-like aggregate evidence.

Evidence packet structure can now be validated with `npm run --silent canvas:qa:packet -- --allow-pending --json --output=artifacts/voice-canvas/YYYY-MM-DD-evidence-packet-summary.json`. The validator checks the packet inventory, flow packet, copy-ready evidence pattern rows, and final pre-fill checklist before QA evidence is copied into the final matrix; reports pending packet cells by section; preserves existing artifacts unless `--force` is explicit; rejects flow packet rows that omit required device, interaction, review, explicit confirmation, no-side-effect, duplicate, stale-response, or rollback/fallback safety coverage; rejects copy-ready evidence patterns that omit required reference, reviewer/date, privacy, no-side-effect, rollback, accessibility, or analytics wording; rejects final pre-fill checklists that omit required artifact, device, interaction, rollback, endpoint, task hub, run-sheet validation, analytics, preflight, or privacy checks; rejects inventory coverage cells that do not map each artifact set to the required launch evidence area; rejects reviewer/date cells older than 7 days; rejects generic prose-only references that do not point to concrete dated sanitized artifact paths or links; and rejects unsafe artifact references without copying raw artifact-reference values into output.

Behavior recovery evidence now has a copy-safe template in the real-device run sheet and evidence packet, so QA must separately name start/resume, app exit/reopen, refresh/reconnect, voice interruption, browser back, cancel/exit, duplicate/stale guard, recoverable failure retry/exit, entered-information preservation, no write, no resubmission, no external action, and artifact privacy before summarizing behavior evidence in the QA matrix.

Launch QA preflight can now be captured with `npm run --silent canvas:qa:preflight -- --json --output=artifacts/voice-canvas/YYYY-MM-DD-launch-preflight.json`. The preflight delegates to the run-sheet, QA matrix, and evidence-packet validators, accepts structurally valid pending evidence before real-device execution, can include sanitized enabled and rollback-disabled endpoint collector artifacts with `--features-enabled=artifacts/voice-canvas/YYYY-MM-DD-feature-endpoints-enabled.json` and `--features-rollback=artifacts/voice-canvas/YYYY-MM-DD-feature-endpoints-rollback-disabled.json`, revalidates those endpoint artifacts for launch scope, matching expected-state label, non-future generated timestamp, deployed HTTPS non-local base URL, and per-flow URLs that match that deployed origin, can include sanitized analytics evidence with `--analytics=artifacts/voice-canvas/YYYY-MM-DD-analytics-evidence.json`, fails final mode with `--final` until the run sheet, matrix, packet, endpoint artifacts, and analytics evidence are ready, preserves existing artifacts unless `--force` is explicit, and is read-only: it does not call feature endpoints, analytics, bookings, calls, messages, navigation, or data writes. Human-readable preflight output now also prints pending sections for the run sheet, QA matrix, and evidence packet, so QA can see exactly which evidence areas remain incomplete without running separate validators.

Preflight output now also includes copy-ready evidence commands for the deployed enabled endpoint capture, deployed rollback-disabled endpoint capture, manifest-filled endpoint trace template, safe analytics evidence template, sanitized analytics validation, run-sheet validation, QA-matrix validation, evidence-packet validation, and final preflight artifact. The commands use the same `YYYY-MM-DD` artifact names and staging-origin placeholder as the launch runbook, so QA can replace the run date and deployed origin without hand-assembling artifact paths or accidentally skipping enabled/rollback/analytics inputs.

The evidence packet and QA matrix now include a dedicated launch preflight artifact inventory row so final sign-off must attach the combined local gate artifact that proves run-sheet, matrix, packet, endpoint, and analytics evidence were checked together.

Launch analytics now treats terminal Shopping `pending` results as completed Canvas launch outcomes, while still excluding Provider Reply `saved` events from completion. This keeps the completed aggregate aligned with user-visible Canvas results without blurring an intermediate save step into task completion.

   - `/api/config/features/ride-voice-canvas`
   - `/api/config/features/appointment-voice-canvas`
   - `/api/config/features/medication-refill-voice-canvas`
   - `/api/config/features/shopping-delivery-voice-canvas`
