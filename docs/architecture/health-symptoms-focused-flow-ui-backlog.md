# Health Symptoms Focused Flow UI Backlog

Status: pending finalized Health Symptoms flow map

## Problem

The current Symptoms detail surface appears as a generic panel below the Health
cards. It is usable, but it does not yet feel like a focused VYVA flow. It also
does not fully apply the newer voice/touch presentation rules.

## Dependency

Do not redesign the live Symptoms panel until the parallel flow task provides a
clear flow map for:

- the canonical Flow and scene IDs;
- the entry question or trigger;
- required and optional user inputs;
- red-flag and escalation rules;
- saved health data that may be shown or reused;
- voice-mode behavior;
- touch-mode behavior;
- final output or handoff state.

## Target Mapping

| Layer | Responsibility |
| --- | --- |
| Flow Catalogue | Owns symptom intake steps, safety checks, expected answers and outcomes. |
| Presentation Registry | Owns the voice-first and touch-card layouts for each step. |
| Health screen | Renders the selected presentation, applies mobile spacing rules and emits canonical events. |

## UI Direction

- Voice mode stays calm and orb-first.
- Touch mode can show cards or detail surfaces, but mobile cards should use
  icon, main label and chevron only.
- Secondary explanatory copy belongs on tablet and desktop unless the current
  step has no other structured UI.
- The bottom navigation must keep clear space and never cover the active
  symptom step.
- Any safety warning or escalation takes priority over ordinary card layout.

## Acceptance Criteria

- Symptoms has a mapped `flowId + sceneId + presentationId` before UI changes.
- Mobile does not show dense helper copy inside cards.
- Voice mode does not show card lists unless the user switches to touch.
- Touch mode exposes the next useful action without forcing the user to scroll.
- The summary or next-step output is generated by the flow, not hardcoded into
  the panel.
